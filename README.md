# 电子纸刷新规划（离线页面）

48×48 黑白像素、固定 3×3 瓦片（每块 16×16），编辑至多 20 帧目标画面；
Worker 在**整段帧序列**上求总费用最小的合法刷新方案（不做逐帧贪心），
页面逐帧展示画面、瓦片残影计数与费用，播放与导出共用同一份求解结果。

## 规则

- 每帧必须让屏幕准确显示该帧目标（第 1 帧相对初始全白计算变化）。
- 每帧二选一：
  - **全屏刷新 F**：费用 `600`，9 块瓦片的残影计数全部清零；
  - **局部刷新 P**：只刷新相对上一帧内容发生变化的瓦片，
    每块费用 `30 + 该瓦片改变像素数`（变黑、变白都算改变），
    被刷瓦片计数 +1，其余不变。
- 任一瓦片计数不得超过 2；计数为 2 的瓦片下一帧若仍变化，则该帧必须全刷。
- 画面完全相同的帧，局刷不刷任何瓦片，费用 0。

## 裁决顺序（同一 (帧, 状态) 去重）

1. 总费用最小；
2. 费用相同，全屏刷新次数较少；
3. 仍相同，按逐帧动作序列字典序，`F < P`（全刷先于局刷）。

求解用三进制编码状态（每瓦片计数 0/1/2，共 3⁹=19683 态），在帧序列上做
动态规划并回溯出每帧动作、费用与计数变化；参考实现
`solveBruteForce` 枚举全部 2^N 条动作序列，测试中与 DP 对拍。

## 文件

- `index.html` / `css/app.css` / `js/app.js` —— 页面（编辑器、逐帧列表、播放器、导出）。
- `js/solver.js` —— 求解器核心，UMD，浏览器与 Node 共用；瓦片数/画面尺寸可配。
- `js/solver-worker.js` —— 经典 Worker，后台跑整段 DP。
- `js/solver-client.js` —— Worker 客户端 + 代际守卫（`LatestRun`）：
  连续编辑时只采用最新一次请求，迟到的旧 Worker 结果静默丢弃；
  Worker 不可用（如 `file://` 受限）时自动退化为同步求解。
- `test/` —— Node 内置测试：
  - `solver.test.js` 手工费用/计数样例、小规模（1×1、2×2 瓦片、1~2 像素瓦片）
    随机帧与朴素全枚举实现穷举对拍、裁决顺序、20 帧生产规模性能；
  - `worker.test.js` Worker 消息往返（reqId/token 透传、错误路径）；
  - `scheduler.test.js` 旧 Worker 结果迟到/乱序/失败时的代际守卫；
  - `app-smoke.test.js` 最小 DOM 桩下加载真实 `app.js` 的整链路冒烟。

## 使用

直接用浏览器打开 `index.html`（离线、无外部依赖；`file://` 下若 Worker
被限制会自动在主线程求解）。或：

```bash
npm test          # 运行全部测试（node --test，无需联网/安装依赖）
```

操作：左栏在像素格上按住拖动绘制，可反相/清空、增删复制帧（≤20），
「载入演示」给出单格闪烁四帧——连续三局刷会越界，整段最优为 `PFPP`
（费用 693，全刷 1 次；两个费用相同的解取全刷更早者）。右栏查看方案总览、
逐帧费用与瓦片计数，并用播放器从初始全白开始逐帧执行；导出按钮下载
包含帧数据与完整方案的 JSON，内容与播放器所用结果为同一份。
